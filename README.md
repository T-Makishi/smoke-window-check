# 排煙窓かんたん事前チェック

排煙窓の修理・点検前に、お客様が問診と写真・動画を選択し、修理費用の目安と現地調査費の条件を確認できるWebアプリです。

公開先はCloudflare Pagesです。会社情報・料金・利用期限はCloudflare D1へ保存し、業者設定APIはCloudflare Accessのメール確認で保護します。問診内容、写真、動画は従来どおりお客様の端末内だけで扱い、Cloudflareへ保存しません。構成と安全上の判断は `CLOUDFLARE_DESIGN.md` を参照してください。

UIはデザインA「信頼感・安心感のあるベーシックデザイン」を採用しています。ダークグリーン、ネイビー、白を基調とし、料金案内だけを淡い黄色で明示しています。最大表示幅は480pxで、iPhone 13と320px幅へ対応しています。主要アイコンは外部ライブラリを使わず、インラインSVGで表示します。

## 主な機能

- 依頼者区分に応じた入力と検証
- 写真・動画3点までの一時プレビュー
- 設定可能なルールベース概算
- 現地調査費と正式依頼時の差し引き条件の明示・同意
- 下書き、相談履歴、編集、複製、削除、対応状況、コピー、印刷
- 保存データのファイル書き出し・読み戻し
- 運営会社、ロゴ、料金、税区分、色、案内文の設定
- 固定受付メール宛ての問診メール作成と、対応端末での画像・動画共有
- 業者ごとの短いお客様用URL
- 7日・14日・30日の試験利用期限
- 期限終了・利用停止時の公開画面制御
- メール確認コードで保護した業者設定
- サービス運営者用の業者登録・期限管理画面
- Webからの7日間無料体験申込、メール確認、業者ID・専用URLの自動発行
- 無料体験申込者一覧、本番利用申込、運営者承認
- 試験終了3日前・1日前の自動案内メール

## ファイル構成

用途別の入口は、業者向けが `trial.html`、見積依頼者向けの会社専用問診が `index.html?t=<発行ID>`、サービス運営者向けが `service.html` です。見積依頼者向けの共通入口は設けず、必ず依頼先業者から届く会社専用URLを使用します。`css/` は変数・リセット・レイアウト・部品・レスポンシブに分割し、`js/` は画面、状態、検証、概算、料金、保存、設定、出力に分割しています。

## 公開構成

- ソースコード: GitHub `T-Makishi/smoke-window-check`
- 公開先: `https://smoke-window-check.pages.dev`
- 本番ブランチ: `main`
- ビルドコマンド: なし
- 出力ディレクトリ: `/`
- D1 binding: `APP_DB`
- サービス運営者メール変数: `SERVICE_ADMIN_EMAIL`
- パスコード用シークレット: `PASSCODE_PEPPER`（32文字以上のランダム値、暗号化して保存）
- メール送信APIキー: `BREVO_API_KEY`（暗号化して保存）
- 送信者メール: `EMAIL_SENDER_ADDRESS`（Brevoで確認済みの送信者）
- 送信者名: `EMAIL_SENDER_NAME`
- 期限案内ジョブ認証: `JOB_SECRET`（32文字以上のランダム値、暗号化して保存）

`main` へのpush後、Cloudflare Pagesが自動でデプロイします。GitHub PagesはCloudflare版の期限確認と認証を検証した後に停止します。

## Cloudflare初期設定

1. D1データベース `smoke-window-check-db` を作成する。
2. D1コンソールで `schema.sql` を実行する。
3. PagesプロジェクトのSettings → Bindingsで、D1を変数名 `APP_DB` に割り当てる。
4. Settings → Variables and Secretsで `SERVICE_ADMIN_EMAIL=makishi0520@gmail.com` を設定する。
5. 同じ画面で32文字以上のランダム値を暗号化シークレット `PASSCODE_PEPPER` として設定する。この値を変更すると登録済みパスコードを再登録する必要があるため、通常運用では変更しない。
6. 設定反映後に本番デプロイを再実行する。
7. Cloudflare Zero TrustでOne-time PINを有効にする。
8. `smoke-window-check.pages.dev/api/vendor/*` と `smoke-window-check.pages.dev/api/service/*` をAccessで保護し、セッション時間を24時間にする。
9. Access通過後もAPI側で認証メールを照合するため、業者はD1に登録したメール、サービス運営者は `SERVICE_ADMIN_EMAIL` だけが操作できる。
10. Pages Functionsの無料枠到達時の動作をFail closedにする。

## 7日間無料体験の自動発行

業者募集用の公開ページは `https://smoke-window-check.pages.dev/trial.html` です。申込者がメール確認を完了すると、7日間有効な業者識別番号、業者設定URL、お客様用URLを自動発行します。既存の運営者画面からの手動登録も継続して利用できます。

申込メールを送信できない場合でも申込情報は保存され、申込者には運営者からの案内を待つ画面を表示します。運営管理画面では確認メールの再送、または本人確認前の手動承認とURL発行ができます。手動承認はメール障害時の予備手段です。

運営管理の標準動作は自動承認です。メール送信設定が有効な場合、申込者が本人確認リンクを開くと専用URLを自動発行するため、自動・手動の切り替え設定はありません。メール送信が未設定の場合は管理画面に「要メール設定」と表示し、手動承認を案内します。確認メール再送と手動承認は各申込の「メール障害時の補助操作」に格納されています。登録業者・試験利用者・申込一覧は折り畳み表示です。未発行申込は申込一覧から削除でき、発行済み利用者は会社名の再入力後に関連する認証・申込・専用URLをまとめて削除できます。

運営管理画面の「運営者メールを変更」では、ログインIDと無料体験申込の通知先を同時に変更できます。現在のパスコードと、新しいメールアドレスへ届く6桁の確認コードが必要です。登録業者や発行済みURLは引き継がれ、再登録は不要です。Cloudflare Accessを特定メールだけの許可リストにしている場合は、変更前に新しいメールもAccessポリシーへ追加してください。メール送信元の `EMAIL_SENDER_ADDRESS` は通知先とは別の設定です。

業者向けランディングページには、導入後の画面を短時間で把握できる静止モックだけを表示します。見積依頼者向けの操作デモページや中間案内ページは設けません。実際の会社専用問診画面には、操作説明、スマートフォン図解、印刷・PDF保存を備えています。

ランディングページは導入を検討する業者専用です。見積依頼者はランディングページを使用せず、依頼先業者から案内された会社専用URLから実際の問診を行います。

本機能を有効化する前に、D1へ `migrations/0002_trial_onboarding.sql` と `migrations/0003_service_admin_email.sql` を順番に適用します。次にBrevoで送信者を確認し、Cloudflare Pagesへ `BREVO_API_KEY`、`EMAIL_SENDER_ADDRESS`、`EMAIL_SENDER_NAME` を登録します。APIキーはGitHubやブラウザ側のJavaScriptへ保存しません。

期限案内はGitHub Actionsの `.github/workflows/trial-reminders.yml` が毎日実行します。同じ32文字以上の値をCloudflareの `JOB_SECRET` とGitHub Actionsの `TRIAL_REMINDER_JOB_SECRET` に登録します。案内は試験終了3日前と1日前に1回ずつ送信され、D1の送信履歴で二重送信を防止します。

本番利用は業者設定画面から相談申込を行い、運営者画面で承認します。申込送信だけでは課金または契約成立になりません。料金・契約条件を別途確認した後、運営者が本番利用へ切り替えます。

設定後は `https://smoke-window-check.pages.dev/service.html` を開き、業者名、業者ログイン用メール、7日・14日・30日の期間を入力して登録します。発行された `?t=...` の会社専用URLをお客様へ共有します。

登録済み業者の会社名またはログイン用メールを修正する場合は、運営者画面の「業者情報を編集」を使用します。ログイン用メールを変更すると旧メールの認証セッションとパスコードは無効になり、新しい担当者がメール確認後にパスコードを初回登録します。業者側からログイン用メールを新規登録・変更することはできません。

## 設定変更

お客様用URLを開き、ヘッダー右上の「業者ログイン」を押します。D1に登録した業者メールへCloudflareから確認コードが届きます。認証後、会社名、受付メール、ロゴ、現地調査費、正式依頼時の差し引き額、税込・税別、概算価格帯を変更して保存します。

## 保存仕様と個人情報

案件、下書き、設定は利用中ブラウザのlocalStorageだけに保存されます。写真・動画の実データは保存も送信もされず、再読み込み後は件数情報だけが残ります。共用端末では案件を保存しないでください。ブラウザデータを削除すると案件も消えます。

履歴画面の「保存データをファイルに書き出す」で、パソコン・スマホのダウンロードフォルダへ保管できます。「保存ファイルから戻す」で追加読み込みできます。内部ファイル形式はJSONです。個別削除または全削除は確認後に実行され、元に戻せません。

## 旧GitHub Pagesとの互換性

`recipient` と `cfg` を含む従来URLは移行確認中のみ利用できます。従来の業者設定は端末内パスコード `1234` の簡易保護です。Cloudflareの `?t=...` URLでは端末内パスコードを使用せず、メール確認を使用します。移行検証後はGitHub Pagesを停止し、従来URLを正式運用へ使用しません。

## 複数症状と印刷

症状は1つ以上、複数選択できます。概算は価格帯が最も高い症状を主症状とし、2件目以降には設定可能な追加確認費を反映します。保存完了、保存履歴、相談詳細の「印刷」からブラウザの印刷画面を開けます。

## 試験メール送信

初期の問診受付メールは `makishi0520@gmail.com` です。保存完了画面の「問診内容をメールで送る」を押すと、端末のメールアプリへ宛先、件名、問診本文を渡します。メールは自動送信されず、お客様が内容を確認して送信操作を行います。

ブラウザの制約により、`mailto:` では写真・動画を自動添付できません。添付ファイルがある場合はメール画面で追加するか、「画像・動画をメール・LINEで共有」から端末の共有機能を利用します。共有機能では送信先が固定されないため、画面に表示された受付メールを確認してください。本番でワンタップ自動送信を実現する場合は、Supabase Storageとメール通知用サーバー処理へ移行します。

### お客様用URL

Cloudflare版のお客様用URLは `https://smoke-window-check.pages.dev/?t=<発行ID>` です。会社情報、受付メール、料金、表示内容、圧縮済みロゴはD1から取得するため、設定変更後も同じ短いURLを継続利用できます。元ロゴ画像はPNG・JPEG・WebP形式、1MB以下です。

お客様がURLを開くたびにD1の利用状態を確認します。期限終了、利用停止、登録なし、D1接続不可の場合は問診を表示しません。お客様の問診データや写真・動画はこの確認処理で送信されません。

設定画面では長い実URLを通常表示しません。「メール用リンクをコピー」を使うと、対応するメールアプリには「排煙窓事前チェックを開く」という短い表示のリンクとして貼り付けられます。端末がHTML形式のクリップボードへ対応していない場合は、案内文と実URLをコピーします。

「LINE用QR画像を作成」では、会社名・案内文・公開設定を含むQRコードを1枚の縦長PNG画像としてブラウザ内で生成します。「LINEなどへ送る」を押して端末の共有画面からLINEを選ぶため、トーク画面へ長い実URLを貼り付けません。QR案内画像はクリップボードへのコピー、PNG保存にも対応します。設定やロゴによりリンクがQRコードの容量を超える場合は発行を停止し、案内文またはロゴの見直しを求めます。QR生成には固定バージョンの `qrcode-generator` を使用し、設定情報を外部のQR作成サービスへ送信しません。
